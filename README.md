## ฐานข้อมูล

ทุกตารางขึ้นต้นด้วย `lf_` เพราะฐานข้อมูลบน Angsila ใช้ร่วมกับ Lab อื่น ถ้าใช้ชื่อเดิม `DROP TABLE users` ใน `setup.sql` จะลบตารางของ Lab อื่นทิ้ง

| ตาราง | เก็บอะไร |
|---|---|
| `lf_users` | บัญชีผู้ใช้ Login ด้วยรหัสนิสิต อีเมลมหาวิทยาลัย สถานะยืนยันอีเมล |
| `lf_categories` | หมวดหมู่สิ่งของ |
| `lf_pickup_points` | จุดรับคืน เช่น ป้อมยาม |
| `lf_items` | ประกาศทั้ง 2 แบบ แยกด้วย `post_type` (`found` = ของที่พบ, `lost` = ตามหาของหาย) |

ประกาศทั้ง 2 แบบใช้สถานะชุดเดียวกัน (`found` → `claimed` → `returned`) และ `return_method` เป็น NULL ได้ เพราะใช้กับของที่พบเท่านั้น ตอนยืนยันคืน SQL ใช้ `IF(post_type = 'found', claimed_by, user_id)` เลือกว่าใครเป็นผู้รับของ (ของที่พบ = ผู้ขอรับคืน, ตามหาของหาย = คนโพสต์ที่เป็นเจ้าของ)

## ฟีเจอร์

- สมัครสมาชิก / Login ด้วยรหัสนิสิต / Logout
- **นิสิต 1 คน = 1 บัญชี** กันบัญชีปลอมมารับของ 3 ชั้น
  1. `student_id` เป็น `UNIQUE` สมัครซ้ำไม่ได้ หน้าเว็บขึ้นว่า "รหัสนิสิตนี้มีบัญชีอยู่แล้ว"
  2. ยืนยันผ่านอีเมลมหาวิทยาลัย: ระบบสร้างอีเมลเป็น `รหัสนิสิต@go.buu.ac.th` ให้เอง แล้วส่งลิงก์ยืนยัน ถ้ายังไม่ยืนยันจะ Login ไม่ได้ ลิงก์ใช้ได้ครั้งเดียว และฐานข้อมูลเก็บเฉพาะ SHA-256 ของโทเคน ถ้าลิงก์หาย Login ด้วยรหัสผ่านที่ถูกต้องระบบจะออกลิงก์ใหม่ให้
  3. ตอนส่งของ ระบบแสดงชื่อและรหัสนิสิตของผู้ขอรับให้เทียบกับบัตรนิสิตจริง และบันทึกผู้รับลง `returned_to` จากบัญชี ไม่มีช่องให้พิมพ์ชื่อเอง
- **จับคู่อัตโนมัติ** หน้ารายละเอียดแสดงการ์ด "อาจเป็นของชิ้นเดียวกัน" จากประกาศฝั่งตรงข้าม (เจอของ ↔ ตามหา) หมวดเดียวกัน วันที่ห่างกันไม่เกิน 7 วัน ยังเปิดอยู่ ไม่ใช่โพสต์ของคนเดียวกัน เรียงจากวันที่ใกล้ที่สุด (self-join `lf_items` + `DATEDIFF` ใช้ index `idx_lf_items_match`)
- **สถิติหน้าแรก** จำนวนของที่คืนสำเร็จ ประกาศที่ยังเปิดอยู่แยกเจอของ / ตามหา และจำนวนประกาศแยกตามหมวด (`SUM`, `COUNT`, `LEFT JOIN`, `GROUP BY`) ผู้ที่ยังไม่ Login เห็นสถิติทั้งมหาวิทยาลัย ส่วนผู้ที่ Login แล้วเห็นสถิติในคณะ
- **แยกประกาศตามคณะ** จากเลขหลักที่ 3-4 ของรหัสนิสิต (เช่น 68**16**0219 → คณะรหัส 16) ผู้ใช้เห็นและขอรับคืนได้เฉพาะประกาศที่คนในคณะเดียวกันโพสต์ ผู้ที่ยังไม่ Login จะเห็นเพียงหน้าแนะนำระบบ
- หน้าแรกแสดงประกาศของคณะตัวเอง ค้นหาจากชื่อของหรือสถานที่ และกรองตามหมวดหมู่ จุดรับคืน สถานะ
- หน้ารายละเอียด แสดงข้อมูลติดต่อหรือจุดรับคืน
- โพสต์ของที่พบ พร้อมรูปภาพ (JPG / PNG ไม่เกิน 2 MB) สถานที่ วันที่ และวิธีคืน
- แก้ไขและลบประกาศ ได้เฉพาะประกาศของตัวเอง
- ขอรับคืน → ยืนยันคืนเรียบร้อย หรือยกเลิกคำขอ (สถานะ ถูกพบ → รอรับคืน → คืนเรียบร้อย)
- **ตามหาของหาย (ตัวเลือกที่ 2 ในหน้าโพสต์ประกาศ)** เจ้าของโพสต์รายละเอียดของที่หาย สถานที่และวันที่หาย พร้อมรูปตัวอย่าง คนในคณะที่เจอของกด "ฉันเจอของชิ้นนี้" แล้วติดต่อเจ้าของ เมื่อได้ของคืน เจ้าของกดยืนยัน (สถานะ กำลังตามหา → มีคนแจ้งว่าเจอ → ได้คืนแล้ว) ถ้าไม่ใช่ของตัวเอง เจ้าของกดยกเลิกเพื่อเปิดประกาศต่อได้
- หน้า "ประกาศของฉัน" แสดงของที่ฉันตามหา ของที่ฉันเจอและโพสต์แจ้ง และรายการที่ฉันขอรับคืน / แจ้งว่าเจอ

## ความปลอดภัย

| ความเสี่ยง | วิธีป้องกันในโค้ด |
|---|---|
| SQL Injection | Prepared Statement ทุก Query ที่รับค่าจากผู้ใช้ |
| รหัสผ่านรั่ว | `password_hash()` / `password_verify()` |
| Session Fixation | `session_regenerate_id(true)` หลัง Login |
| แก้ / ลบประกาศของคนอื่น | `AND user_id = ?` ใน WHERE ของ UPDATE / DELETE |
| ปลอมตัวตนผู้รับของ | ใช้ user_id จาก `$_SESSION` เท่านั้น / ผู้รับของบันทึกจากบัญชี ไม่มีช่องพิมพ์ชื่อ |
| สมัครหลายบัญชี / บัญชีปลอม | `student_id` และ `email` เป็น `UNIQUE` + ต้องยืนยันผ่านอีเมล `รหัสนิสิต@go.buu.ac.th` ก่อน Login |
| โทเคนยืนยันรั่วจากฐานข้อมูล | เก็บเฉพาะ SHA-256 ของโทเคน และล้างทิ้งทันทีหลังยืนยัน (ใช้ได้ครั้งเดียว) |
| ลบตารางของ Lab อื่นในฐานข้อมูลที่ใช้ร่วมกัน | ทุกตารางขึ้นต้น `lf_` และ `setup.sql` DROP เฉพาะตาราง `lf_` |
| เปิดดู / ขอรับคืนประกาศของคณะอื่นโดยแก้ `?id=` | ใส่ `SUBSTRING(student_id, 3, 2) = ?` (รหัสคณะจาก Session) ใน WHERE ของหน้ารายละเอียดและการขอรับคืน |
| CSRF | CSRF Token ในทุกฟอร์มที่เปลี่ยนข้อมูล (รวมถึง Logout) |
| อัปโหลดไฟล์อันตราย | ตรวจเนื้อไฟล์ด้วย `getimagesize()` รับเฉพาะ JPG / PNG ≤ 2 MB และตั้งชื่อไฟล์ใหม่แบบสุ่ม |
| XSS | แสดงข้อความผู้ใช้ผ่าน `htmlspecialchars()` |

## วิธีติดตั้ง

1. **นำเข้าฐานข้อมูล**
   - เปิด phpMyAdmin แล้วเลือกฐานข้อมูลของตัวเอง
   - ไปที่แท็บ **SQL** (หรือ **Import**) แล้วนำเข้าไฟล์ `database/setup.sql` จากนั้นกด **Go**
   - ไฟล์นี้สร้างเฉพาะตาราง `lf_` ไม่แตะตารางอื่น ถ้าเคยนำเข้า `setup.sql` เวอร์ชันแรก (ตาราง `users`, `items`, `categories`, `pickup_points`, `lost_items`) ตารางเก่าจะยังอยู่ ให้ตรวจก่อนว่าไม่ใช่ตารางของ Lab อื่น แล้วค่อยลบเองใน phpMyAdmin
2. **ตั้งค่าการเชื่อมต่อฐานข้อมูล**
   - ก๊อปไฟล์ `config/db.example.php` แล้วเปลี่ยนชื่อเป็น `config/db.php`
   - แก้ค่า host, user, password และชื่อฐานข้อมูลใน `config/db.php` เป็นของตัวเอง
   - `VERIFY_DEMO_MODE` = `true` (ค่าเริ่มต้น) แสดงลิงก์ยืนยันอีเมลบนหน้าจอแทนการส่งอีเมล เพราะ Angsila อาจส่งอีเมลไม่ได้ ถ้าเซิร์ฟเวอร์ส่งอีเมลได้ ตั้งเป็น `false`
   - ไฟล์ `config/db.php` ถูก ignore ไว้ใน `.gitignore` จึงไม่ถูกขึ้น GitHub
3. วางโฟลเดอร์โปรเจคไว้บนเว็บเซิร์ฟเวอร์ที่รัน PHP 7.0 ขึ้นไป (ต้องมี mysqli + mysqlnd) แล้วเปิดผ่านเบราว์เซอร์
4. ตั้งสิทธิ์โฟลเดอร์ `uploads/` ให้เว็บเซิร์ฟเวอร์เขียนไฟล์ได้ (เช่น 775 หรือ 777 แล้วแต่เซิร์ฟเวอร์) เพื่อให้อัปโหลดรูปได้
